**Omega-log** คือเครื่องมือในชุด `omega-` ที่ใช้สำหรับจัดการ อ่าน และวิเคราะห์ไฟล์ล็อกของเซิร์ฟเวอร์ผ่าน TUI — ตรวจหาบริการที่ทำงานอยู่และล็อกของบริการเหล่านั้นโดยอัตโนมัติ คลังกลาง โหมดการอ่านสามแบบ (ติดตามแบบง่าย อ่านแบบคลาสสิก และผสานหลายไฟล์ผ่าน `lnav`) การจัดการ IP สถิติ การหมุนเวียน/สำรอง/กู้คืน การล้างอย่างปลอดภัย และการส่งออก สร้างขึ้นด้วยการ **พอร์ตและดัดแปลง** โค้ดที่พัฒนามาอย่างดีแล้วจาก [omega-fire](https://github.com/kraynux) และ [omega-serv](https://github.com/kraynux) แทนการเขียนใหม่ทั้งหมดตั้งแต่ศูนย์

## 1. วิสัยทัศน์และขอบเขต

Omega-log ตอบคำถามง่าย ๆ ข้อเดียว: « เกิดอะไรขึ้นในล็อกของฉัน และฉันจะจัดการมันอย่างไร? » — โดยไม่ต้องพึ่งรายการพาธที่รู้จักแบบตายตัว ไม่ทำงานในฐานะ root เป็นค่าเริ่มต้นเด็ดขาด และไม่ทำให้ไฟล์ล็อกจริงสูญหายหรือเสียหายแบบเงียบ ๆ เด็ดขาด

### สิ่งที่ Omega-log ทำ

- ตรวจหาบริการที่ทำงานอยู่บนเครื่องโดยอัตโนมัติ (เว็บเซิร์ฟเวอร์ ฐานข้อมูล อีเมล DNS ความปลอดภัย `omega-serv`...) และเสนอให้นำเข้าล็อกที่รู้จักของบริการเหล่านั้น ทีละรายการหรือทั้งหมด — นอกเหนือจากการสแกนโฟลเดอร์ใดก็ได้ด้วยตนเอง
- รวบรวมล็อกที่ต้องจัดการไว้ใน คลัง เพียงแห่งเดียว ซึ่งเป็นจุดเริ่มต้นของหน้าจออื่นทั้งหมด
- อ่านล็อกได้สามโหมดตามความต้องการ: ติดตามแบบง่ายพร้อมการแยกวิเคราะห์และสถิติ อ่านแบบคลาสสิกแบบดิบพร้อมติดตามสด หรือผสานหลายไฟล์โดยห่อหุ้ม `lnav`
- จดจำชุดล็อก + ตัวดู ไว้เป็น รายการโปรด เพื่อเปิดใช้งานได้ทันที
- คำนวณ 10 อันดับ IP ตามช่วงเวลา หรือค้นหา IP ที่ระบุ และลบ IP นั้นแบบเจาะจงออกจากไฟล์หนึ่งหรือหลายไฟล์
- คำนวณสถิติการเข้าถึง (ปริมาณ IP ที่ไม่ซ้ำ อัตราข้อผิดพลาด การกระจายรายชั่วโมง) ซึ่งส่งออกเป็น JSON หรือ HTML ตามธีมได้
- สำรอง (บีบอัด + การเก็บรักษาอัตโนมัติ) ด้วยตนเองหรือทุกคืนผ่านการสำรองข้อมูลตามกำหนด กู้คืน (ผสานหรือเขียนทับ พร้อมการสำรองเพื่อความปลอดภัย) และล้าง (ตัดทอนในที่เดิมหรือลบ) ไฟล์ล็อก โดยต้องยืนยันอย่างชัดเจนทุกครั้ง
- ตรวจสอบสุขภาพล็อก (สิทธิ์ ล็อกที่เงียบหรือเสียหาย พื้นที่ดิสก์ การสำรอง) และบอกว่าต้องทำอะไรสำหรับแต่ละข้อที่พบ
- ปรับตัวตามความสามารถของเทอร์มินัลโดยอัตโนมัติ (สี ขนาด) ผ่าน `omega-lib` เช่นเดียวกับเครื่องมืออื่นในชุด

### สิ่งที่ Omega-log ไม่ทำ

| ฟังก์ชัน | เครื่องมือที่รับผิดชอบ |
|---|---|
| ไฟร์วอลล์ กฎเครือข่าย การตรวจจับการบุกรุก | OMEGA-FIRE |
| เว็บเซิร์ฟเวอร์ reverse proxy WAF Active Defense | OMEGA-SERV |
| สแกนพอร์ต ระบุบริการเครือข่าย | OMEGA-CHECK |
| สังเกตการณ์เครือข่าย ตัวตนดิจิทัลของเป้าหมาย | OMEGA-TRACK |

ยังไม่มี CLI ที่ทำได้เทียบเท่า TUI ทั้งหมด (โหมดบรรทัดคำสั่งปัจจุบันครอบคลุมเพียงการสแกนบริการ ดู §3.2) ไม่มีการรวบรวมล็อกจากหลายเครื่องไว้ที่ศูนย์กลาง และไม่มีการแจ้งเตือนแบบเรียลไทม์ตามเกณฑ์ — Omega-log ยังคงเป็นเครื่องมือตรวจสอบและบำรุงรักษาภายในเครื่อง ไม่ใช่ SIEM

### คำเตือนการใช้งาน

การดำเนินการบำรุงรักษา (**ล้าง**, **Rotate → กู้คืน ในโหมดเขียนทับ**) จะแก้ไขหรือลบเนื้อหาจริงของไฟล์ล็อกของคุณอย่างถาวร — ก่อนดำเนินการจะมีการยืนยันอย่างชัดเจนพร้อมรายละเอียดไฟล์ที่เกี่ยวข้องเสมอ และไม่เคยทำงานโดยอัตโนมัติ หากไม่แน่ใจ ให้สำรองก่อน (**Rotate → สำรองข้อมูลเดี๋ยวนี้**)

## 2. การติดตั้ง

### ข้อกำหนดเบื้องต้น

- Python 3.10+
- Linux (ทดสอบแล้วบน Arch/Manjaro, Debian/Ubuntu, RHEL/Fedora)
- ติดตั้ง `lnav` บนระบบ เฉพาะสำหรับตัวดูแบบผสานหลายไฟล์ (ตัวดูอีกสองแบบทำงานได้ตามปกติโดยไม่ต้องมี):

```bash
# Arch / Manjaro
sudo pacman -S lnav

# Debian / Ubuntu
sudo apt install lnav
```

### การติดตั้ง

```bash
[ -d omega-log ] && echo "ℹ️ แตกไฟล์ไว้ที่นี่แล้ว ข้ามขั้นตอนนี้" || tar -xzf omega-log-1.6.0.tar.gz
cd omega-log/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. สร้างสภาพแวดล้อมเสมือน `.venv` หากยังไม่มี
2. ติดตั้ง dependency (`omega-lib` ที่แนบมา (vendored) ก่อนถ้ามี จากนั้น `pip install -e .` — `pyproject.toml` ยังคงเป็นแหล่งข้อมูลจริงเพียงแหล่งเดียว)
3. ทำให้ `omega-log.sh` และ `install.sh` เรียกใช้งานได้
4. ตรวจสอบว่ามี `lnav` หรือไม่ (แจ้งเตือนเพื่อทราบหากไม่มี ไม่เคยขัดขวางการติดตั้ง)
5. เพิ่ม alias `log` ลงใน `~/.bashrc` และ `~/.zshrc` (ไม่ซ้ำหากมีอยู่แล้ว)

### Dependency

ประกาศไว้ใน `pyproject.toml` (ไม่มี `requirements.txt` แยก):
- `omega-lib`: ไลบรารีที่ใช้ร่วมกันของชุดเครื่องมือ (ธีม TUI + การส่งออก การตรวจหาเทอร์มินัล การจัดเก็บการตั้งค่า)
- `textual`: อินเทอร์เฟซ TUI
- `jinja2`: การส่งออก HTML ตามธีม (สถิติ ไฟล์เก็บถาวร)
- `pyte`: การจำลองเทอร์มินัลสำหรับตัวดู `lnav` (แสดงผลใน pty ที่ห่อหุ้มไว้)
- Dependency สำหรับการพัฒนา (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `ruff`, `mypy`

## 3. การใช้งาน

### 3.1. โหมดโต้ตอบ (TUI)

แนะนำสำหรับการใช้งานประจำวัน — เปิดโดยไม่ใส่อาร์กิวเมนต์:

```bash
./omega-log.sh
```
หากคุณสร้าง alias ไว้แล้ว เพียงพิมพ์ `log` ในเทอร์มินัลใหม่:
```bash
log
```

ลำดับการใช้งานโดยรวม: หน้าจอเริ่มต้น → เมนูหลัก (สองคอลัมน์ — ทะเบียนความสามารถ/คลัง/ดูล็อก/รายการโปรด/ดูและจัดการ IP/สถิติ (การเข้าถึง) ด้านหนึ่ง และ Rotate/ล้าง/ส่งออก/สุขภาพล็อก/ตัวเลือก/ช่วยเหลือ อีกด้านหนึ่ง) → หน้าจอของฟังก์ชันที่เลือก → กลับไปยังเมนู (`Esc`) ความช่วยเหลือฉบับสมบูรณ์ (`a`) อธิบายทุกหน้าจอ ทุกตัวดู และแนวคิดที่ใช้ร่วมกัน (การยกระดับสิทธิ์ sudo เป็นครั้งคราว สถานะของล็อก การเลือกด้วยหมายเลข) — ดู §4 สำหรับสาระสำคัญ

#### ปุ่มลัด

| ปุ่ม | การทำงาน |
|---|---|
| `↑` / `↓` | เลื่อนระหว่างรายการในหน้าจอ |
| `Tab` / `Shift+Tab` | เลื่อนระหว่างช่องในฟอร์ม |
| `Esc` | กลับไปหน้าจอก่อนหน้า (ยืนยันการออกเมื่ออยู่ที่หน้าแรก) |
| `t` | ธีมถัดไป (ใช้ทันที ไม่ต้องยืนยัน) |
| `r` | รีเฟรชการตรวจหาเทอร์มินัล |
| `a` | แสดงความช่วยเหลือ (ครบถ้วน หนึ่งบทต่อหนึ่งหน้าจอ) |
| `q` | ออก (พร้อมการยืนยัน) |

### 3.2. โหมดบรรทัดคำสั่ง (CLI)

ยังทำได้ไม่เทียบเท่า TUI ทั้งหมด (รายการโปรด การล้าง... จะตามมาในระยะการพัฒนาของแต่ละส่วน ดู `plan_omega_log.md` §12):

```bash
# ตรวจหาบริการที่ทำงานอยู่และล็อกที่รู้จักของบริการเหล่านั้น
python -m omega_log scan

# + สแกนโฟลเดอร์เพิ่มเติมด้วยตนเอง
python -m omega_log scan --path /var/log

# เวอร์ชันที่ติดตั้ง และเปรียบเทียบกับเวอร์ชันล่าสุดที่เผยแพร่
python -m omega_log version --check

# การสำรองข้อมูลตามกำหนดที่ถึงกำหนดแล้ว (เรียกทุกคืนโดย timer ของ systemd หรือ crontab)
python -m omega_log rotate run-automations
```

### 3.3. ตัวแปรสภาพแวดล้อม

| ตัวแปร | ผล |
|---|---|
| `OMEGA_LOG_VAR_DIR` | เปลี่ยนตำแหน่งของโฟลเดอร์สถานะของแอปพลิเคชัน (ค่าเริ่มต้น `./var` สัมพัทธ์กับโฟลเดอร์ที่เปิดใช้งาน) |
| `OMEGA_LOG_LANG` | บังคับภาษาของอินเทอร์เฟซสำหรับเซสชันนั้น (เช่น `en`, `de`, `ja`) โดยไม่เปลี่ยนค่าที่บันทึกไว้ |

## 4. ฟังก์ชัน

| หน้าจอ | คำอธิบาย |
|---|---|
| **ทะเบียนความสามารถ** | ตรวจหาบริการที่ทำงานอยู่บนเครื่องและเสนอให้นำเข้าล็อกที่รู้จักของบริการเหล่านั้น ทีละรายการหรือทั้งหมด พร้อมการสแกนโฟลเดอร์ด้วยตนเองเพิ่มเติม |
| **คลัง** | ศูนย์กลางที่อ้างอิงล็อกทั้งหมดที่ต้องจัดการ — ป้อนข้อมูลจากทะเบียน จากการนำเข้าด้วยตนเอง จากล็อกที่รู้จักของ Omega-Serv หรือจากสำเนาที่ดึงมาผ่าน SSH |
| **ดูล็อก** | เลือกล็อกหนึ่งหรือหลายรายการจากคลัง + เลือกตัวดู (1 ล็อก → ตัวดูทั้ง 3 แบบ; 2 ล็อกขึ้นไป → `lnav` เท่านั้น) |
| **รายการโปรด** | ชุดล็อก + ตัวดู ที่บันทึกไว้ภายใต้ชื่อหนึ่ง เพื่อเปิดใช้งานได้ทันที |
| **ดูและจัดการ IP** | 10 อันดับ IP ตามช่วงเวลา (24 ชม./7 วัน/30 วัน/ทั้งหมด) หรือค้นหา IP ที่ระบุ (IPv4 หรือ IPv6) และลบ IP แบบเจาะจงออกจากล็อกหนึ่งหรือหลายไฟล์ |
| **สถิติ (การเข้าถึง)** | ปริมาณ IP ที่ไม่ซ้ำ อัตราข้อผิดพลาด IP อันดับต้น การกระจายรายชั่วโมง — ส่งออก JSON/HTML ได้ 5 ธีม |
| **Rotate** | สำรองล็อกแบบบีบอัด + การเก็บรักษาอัตโนมัติที่ลบไฟล์เก็บถาวรส่วนเกิน + การกู้คืน (ผสานหรือเขียนทับ พร้อมการสำรองเพื่อความปลอดภัย) **การสำรองข้อมูลตามกำหนด**: สำรองล็อกทุกวัน ทุกสัปดาห์ หรือทุกเดือน ทำงานทุกคืนโดย timer ของ systemd หรือบรรทัดหนึ่งใน crontab ของคุณ (OpenRC, runit) ภายใต้บัญชีของคุณ ไม่ใช่ root เด็ดขาด |
| **ล้าง** | ล้างเนื้อหาของล็อก (ตัดทอนในที่เดิม ปลอดภัยสำหรับบริการที่ยังเปิดไฟล์อยู่) หรือลบไฟล์หนึ่งหรือหลายไฟล์ทั้งหมด — ต้องยืนยันทุกครั้ง |
| **ส่งออก** | ส่งออกรายการไฟล์เก็บถาวร (Rotate) เป็น JSON หรือ HTML ตามธีม |
| **สุขภาพล็อก** | ตรวจสอบแบบอ่านอย่างเดียวสำหรับล็อกในคลัง ดิสก์ การสำรอง และการสำรองข้อมูลตามกำหนด: สิทธิ์ ล็อกที่เงียบหรือเสียหาย วันที่ logrotate จำนวนวันก่อนดิสก์เต็ม พร้อมสิ่งที่ต้องทำ แก้ไขสิทธิ์ที่เปิดกว้างเกินไป (ใช้ sudo หากจำเป็น) ส่งออก JSON/HTML/TXT |
| **ตัวเลือก** | ธีม โปรไฟล์การแสดงผล ภาษาของอินเทอร์เฟซและภาษาของการส่งออก (17 ภาษา) ล้างโฟลเดอร์ของแอปพลิเคชัน (exports/screenshots) |

### ตัวดูทั้ง 3 แบบ

1. **แบบง่าย** — ติดตามสดพร้อมการแยกวิเคราะห์ทั่วไป (เวลา IP ระดับ บริการ) และตารางสถิติขนาดเล็ก สำหรับ access log ของ HTTP ที่รู้จัก จะมีคอลัมน์เพิ่ม รหัส HTTP / ความหน่วง ซึ่งมีสีตามเกณฑ์
2. **แบบคลาสสิก** — อ่านบรรทัดดิบล่าสุด + สลับ « ติดตามสด » โดยไม่มีการแยกวิเคราะห์: ง่ายที่สุดและเชื่อถือได้มากที่สุดไม่ว่ารูปแบบใด
3. **lnav** — ผสานหลายไฟล์ในเทอร์มินัลที่ห่อหุ้มไว้ (pty) เพื่อการวิเคราะห์ข้ามไฟล์ วนเปลี่ยนธีม (`t`) ทำเครื่องหมาย + คัดลอกไปยังคลิปบอร์ด (`Ctrl+C`, OSC 52) ออก (`Ctrl+Q`) — ทั้งหมดถูกดักไว้ก่อนถึง `lnav` เอง

## 5. ความเข้ากันได้ของเทอร์มินัล

TUI (Textual) ตรวจหาความสามารถของเทอร์มินัลโดยอัตโนมัติ (อีมูเลเตอร์ ขนาด) และปรับสไตล์ชีตเชิงโครงสร้างให้เหมาะสม (`complete`/`standard`/`reduced`/`mono`) โดยไม่ต้องใช้แฟล็กด้วยตนเอง — นโยบายเดียวกันที่ใช้ร่วมกันทั้งชุด `omega-` (`omega-lib`, `terminal/policies.py`) รีเฟรชได้ทันทีด้วยปุ่ม `r`

### โปรไฟล์ตามอีมูเลเตอร์ที่ตรวจพบ

| อีมูเลเตอร์ | โปรไฟล์เริ่มต้น |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, SSH รุ่นใหม่ | `reduced` |
| TTY Linux, SSH รุ่นเก่า | `mono` |
| อีมูเลเตอร์ที่ไม่รู้จัก | `reduced` (ค่าสำรองเริ่มต้น) |

### โปรไฟล์ตามขนาดเทอร์มินัล

| ขนาดขั้นต่ำ (คอลัมน์ × บรรทัด) | เพดานโปรไฟล์ |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| ต่ำกว่านั้น | `mono` |

โปรไฟล์สุดท้ายที่ใช้คือ **โปรไฟล์ที่เข้มงวดที่สุดในสองแบบ** (อีมูเลเตอร์และขนาด)

## 6. สถาปัตยกรรม

Clean Architecture (domain / application / infrastructure / interfaces) แบบแผนเดียวกับเครื่องมืออื่นในชุด OMEGA:

```text
src/omega_log/
├── core/            ทะเบียนความสามารถ (การตรวจหาบริการ)
├── domain/          ตรรกะทางธุรกิจล้วน (การแยกวิเคราะห์ สถิติ การหมุนเวียน การล้าง)
├── ports/           สัญญา (Protocol)
├── application/     กรณีการใช้งาน
├── infrastructure/  การใช้งานจริง (probes การจัดเก็บ ไฟล์เก็บถาวร การส่งออก lnav การทำงานพร้อมกัน)
├── interfaces/      TUI (Textual) + CLI
└── app/             Composition root
```

ขึ้นอยู่กับ [`omega-lib`](../../../../LIB/omega-lib) สำหรับธีม (10 ธีม TUI + 5 ธีมการส่งออก) การตรวจหาเทอร์มินัล และการจัดเก็บการตั้งค่า — รากฐานเดียวกับเครื่องมืออื่นในชุด การคำนวณหนัก (IP อันดับต้น สถิติการเข้าถึง) ทำงานใน `ProcessPoolExecutor` เฉพาะ (`infrastructure/concurrency/`) ไม่เคยทำงานบนเธรดของอินเทอร์เฟซ เพื่อให้ตอบสนองได้ดีแม้กับไฟล์ที่มีหลายแสนบรรทัด

## 8. สถานะการพัฒนา

ทั้ง 10 ระยะของแผนการพัฒนาเสร็จสมบูรณ์แล้ว: รากฐาน domain TUI พื้นฐาน ตัวดู รายการโปรด/คลัง/IP การบำรุงรักษา สถิติ/การส่งออก การปิดงาน การยกระดับสิทธิ์ sudo เป็นครั้งคราว การย้ายการคำนวณที่ใช้ CPU หนักไปยังโปรเซสแยก — ดู `plan_omega_log.md` สำหรับรายละเอียดของการตัดสินใจในการพอร์ตแต่ละครั้ง ตั้งแต่เวอร์ชัน 1.6.0 ได้นำความสามารถใหม่ของตัวจัดการล็อกใน omega-serv 2.6.0 มาใช้: สุขภาพล็อก การสำรองข้อมูลตามกำหนด การค้นหา IP ที่ระบุ การแสดงเวอร์ชัน และการตรวจสอบการอัปเดต
