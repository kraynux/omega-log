**Omega-log** `omega-` सूट का वह टूल है जो TUI में सर्वर लॉग फ़ाइलों के प्रबंधन, पढ़ने और विश्लेषण के लिए समर्पित है — सक्रिय सेवाओं और उनके लॉग का स्वचालित पता लगाना, केंद्रीय लाइब्रेरी, पढ़ने के तीन मोड (सरल फ़ॉलो, क्लासिक पठन, `lnav` के ज़रिए कई फ़ाइलों का विलय), IP का संसाधन, आँकड़े, रोटेशन/बैकअप/रिस्टोर, सुरक्षित सफ़ाई और एक्सपोर्ट। इसे शून्य से दोबारा लिखने के बजाय [omega-fire](https://github.com/kraynux) और [omega-serv](https://github.com/kraynux) के पहले से परिपक्व कोड के **पोर्टिंग और अनुकूलन** से बनाया गया है।

## 1. दृष्टि और दायरा

Omega-log एक सीधे सवाल का जवाब देता है: «मेरे लॉग में क्या हो रहा है, और मैं उन्हें कैसे संभालूँ?» — ज्ञात पथों की किसी तय सूची पर निर्भर हुए बिना, डिफ़ॉल्ट रूप से कभी root के रूप में चले बिना, और किसी वास्तविक लॉग फ़ाइल को कभी चुपचाप खोए या बिगाड़े बिना।

### Omega-log क्या करता है

- मशीन पर सक्रिय सेवाओं (वेब सर्वर, डेटाबेस, मेल, DNS, सुरक्षा, `omega-serv`...) का स्वचालित पता लगाता है और उनके ज्ञात लॉग को एक-एक करके या सभी को एक साथ इम्पोर्ट करने का प्रस्ताव देता है — किसी भी फ़ोल्डर के मैनुअल स्कैन के अतिरिक्त।
- संसाधित किए जाने वाले लॉग को एक ही लाइब्रेरी में केंद्रित करता है, जो बाकी सभी स्क्रीन का प्रवेश बिंदु है।
- ज़रूरत के अनुसार तीन मोड में लॉग पढ़ता है: पार्सिंग और आँकड़ों के साथ सरल फ़ॉलो, लाइव फ़ॉलो के साथ कच्चा क्लासिक पठन, या `lnav` को समाहित करके कई फ़ाइलों का विलय।
- लॉग + व्यूअर के संयोजनों को पसंदीदा के रूप में याद रखता है, ताकि उन्हें सीधे खोला जा सके।
- अवधि के अनुसार शीर्ष 10 IP निकालता है, या किसी विशिष्ट IP को खोजता है, और एक या अधिक फ़ाइलों से उन्हें लक्षित रूप से हटाने देता है।
- एक्सेस आँकड़े (मात्रा, अद्वितीय IP, त्रुटि दर, प्रति घंटा वितरण) निकालता है, जिन्हें JSON या थीम वाले HTML में एक्सपोर्ट किया जा सकता है।
- लॉग फ़ाइलों का बैकअप लेता है (संपीड़न + स्वचालित रिटेंशन), हाथ से या निर्धारित बैकअप के ज़रिए हर रात, उन्हें रिस्टोर करता है (मर्ज या प्रतिस्थापन, सुरक्षा बैकअप के साथ) और साफ़ करता है (उसी जगह ट्रंकेशन या हटाना), हमेशा स्पष्ट पुष्टि के साथ।
- लॉग के स्वास्थ्य की जाँच करता है (अनुमतियाँ, मौन या क्षतिग्रस्त लॉग, डिस्क पर जगह, बैकअप) और हर निष्कर्ष के लिए बताता है कि क्या करना है।
- बाकी सूट की तरह, `omega-lib` के ज़रिए टर्मिनल की क्षमताओं (रंग, आकार) के अनुसार स्वयं को स्वचालित रूप से ढालता है।

### Omega-log क्या नहीं करता

| कार्य | ज़िम्मेदार टूल |
|---|---|
| फ़ायरवॉल, नेटवर्क नियम, घुसपैठ का पता लगाना | OMEGA-FIRE |
| वेब सर्वर, रिवर्स प्रॉक्सी, WAF, Active Defense | OMEGA-SERV |
| पोर्ट स्कैन, नेटवर्क सेवाओं की पहचान | OMEGA-CHECK |
| नेटवर्क अवलोकन, किसी लक्ष्य की डिजिटल पहचान | OMEGA-TRACK |

TUI के पूर्ण बराबर CLI (अभी) नहीं है (वर्तमान कमांड-लाइन मोड केवल सेवाओं के स्कैन को कवर करता है, देखें §3.2), कई मशीनों का केंद्रीकृत एकत्रीकरण नहीं, सीमा-आधारित रीयल-टाइम अलर्टिंग नहीं — Omega-log स्थानीय निरीक्षण और रखरखाव का टूल है, SIEM नहीं।

### उपयोग संबंधी चेतावनी

रखरखाव की क्रियाएँ (**साफ़ करें**, **Rotate → प्रतिस्थापन (overwrite) मोड में रिस्टोर करें**) आपकी लॉग फ़ाइलों की वास्तविक सामग्री को स्थायी रूप से बदल या मिटा देती हैं — इनसे पहले हमेशा संबंधित फ़ाइलों का विवरण देने वाली स्पष्ट पुष्टि होती है, ये कभी स्वचालित रूप से शुरू नहीं होतीं। संदेह होने पर, कुछ करने से पहले बैकअप लें (**Rotate → अभी बैकअप लें**)।

## 2. इंस्टॉलेशन

### पूर्वापेक्षाएँ

- Python 3.10+
- Linux (Arch/Manjaro, Debian/Ubuntu, RHEL/Fedora पर परीक्षित)
- सिस्टम पर `lnav` इंस्टॉल हो, केवल कई फ़ाइलों के विलय वाले व्यूअर के लिए (बाकी दोनों व्यूअर इसके बिना सामान्य रूप से काम करते हैं):

```bash
# Arch / Manjaro
sudo pacman -S lnav

# Debian / Ubuntu
sudo apt install lnav
```

### इंस्टॉलेशन

```bash
[ -d omega-log ] && echo "ℹ️ यहाँ पहले से एक्सट्रैक्ट है, यह चरण छोड़ा गया।" || tar -xzf omega-log-1.6.0.tar.gz
cd omega-log/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. वर्चुअल एनवायरनमेंट `.venv` बनाता है, यदि वह पहले से मौजूद नहीं है।
2. निर्भरताएँ इंस्टॉल करता है (यदि मौजूद हो तो पहले साथ में शामिल `omega-lib`, फिर `pip install -e .` — `pyproject.toml` ही सत्य का एकमात्र स्रोत रहता है)।
3. `omega-log.sh` और `install.sh` को निष्पादन योग्य बनाता है।
4. `lnav` की उपस्थिति जाँचता है (अनुपस्थित होने पर सूचनात्मक चेतावनी, कभी अवरोधक नहीं)।
5. `~/.bashrc` और `~/.zshrc` में उपनाम `log` जोड़ता है (पहले से मौजूद हो तो दोहराव के बिना)।

### निर्भरताएँ

`pyproject.toml` में घोषित (अलग `requirements.txt` नहीं):
- `omega-lib`: सूट की साझा लाइब्रेरी (TUI + एक्सपोर्ट थीम, टर्मिनल पहचान, सेटिंग्स का भंडारण)
- `textual`: TUI इंटरफ़ेस
- `jinja2`: थीम वाला HTML एक्सपोर्ट (आँकड़े, आर्काइव)
- `pyte`: `lnav` व्यूअर के लिए टर्मिनल अनुकरण (समाहित pty में रेंडरिंग)
- विकास निर्भरताएँ (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `ruff`, `mypy`

## 3. उपयोग

### 3.1. इंटरैक्टिव मोड (TUI)

रोज़मर्रा के उपयोग के लिए अनुशंसित — बिना तर्क के चलाया जाता है:

```bash
./omega-log.sh
```
यदि आपने उपनाम बनाया है, तो किसी नए टर्मिनल में बस `log` टाइप करें:
```bash
log
```

सामान्य क्रम: स्टार्टअप स्क्रीन → मुख्य मेनू (दो कॉलम — एक ओर क्षमता रजिस्टर/लाइब्रेरी/लॉग देखें/पसंदीदा/IP देखें और संसाधित करें/आँकड़े (एक्सेस), दूसरी ओर Rotate/साफ़ करें/एक्सपोर्ट/लॉग स्वास्थ्य/विकल्प/सहायता) → चुने गए कार्य की स्क्रीन → मेनू पर वापसी (`Esc`)। पूर्ण सहायता (`a`) हर स्क्रीन, हर व्यूअर और साझा अवधारणाओं (एक बार का sudo उन्नयन, लॉग की स्थितियाँ, संख्याओं द्वारा चयन) का विस्तार से वर्णन करती है — मुख्य बातों के लिए §4 देखें।

#### कीबोर्ड शॉर्टकट

| कुंजी | क्रिया |
|---|---|
| `↑` / `↓` | किसी स्क्रीन के तत्वों के बीच नेविगेट करें |
| `Tab` / `Shift+Tab` | किसी फ़ॉर्म के फ़ील्ड के बीच नेविगेट करें |
| `Esc` | पिछली स्क्रीन पर वापसी (स्वागत स्क्रीन पर बाहर निकलने की पुष्टि) |
| `t` | अगली थीम (तुरंत लागू, बिना पुष्टि के) |
| `r` | टर्मिनल पहचान को ताज़ा करें |
| `a` | सहायता दिखाएँ (विस्तृत, हर स्क्रीन के लिए एक अध्याय) |
| `q` | बाहर निकलें (पुष्टि के साथ) |

### 3.2. कमांड-लाइन मोड (CLI)

TUI के साथ अभी पूर्ण बराबरी नहीं है (पसंदीदा, सफ़ाई... अपने-अपने चरणों के साथ आएँगे, देखें `plan_omega_log.md` §12):

```bash
# सक्रिय सेवाओं और उनके ज्ञात लॉग का पता लगाता है
python -m omega_log scan

# + एक अतिरिक्त फ़ोल्डर का मैनुअल स्कैन
python -m omega_log scan --path /var/log

# इंस्टॉल किया गया संस्करण, और नवीनतम प्रकाशित संस्करण से तुलना
python -m omega_log version --check

# समय पर पहुँचे निर्धारित बैकअप (हर रात systemd टाइमर या crontab द्वारा चलाया जाता है)
python -m omega_log rotate run-automations
```

### 3.3. एनवायरनमेंट वेरिएबल

| वेरिएबल | प्रभाव |
|---|---|
| `OMEGA_LOG_VAR_DIR` | एप्लिकेशन स्थिति फ़ोल्डर का स्थान बदलता है (डिफ़ॉल्ट `./var`, लॉन्च फ़ोल्डर के सापेक्ष) |
| `OMEGA_LOG_LANG` | सत्र के लिए इंटरफ़ेस की भाषा तय करता है (उदा. `en`, `de`, `ja`), सहेजी गई सेटिंग बदले बिना |

## 4. सुविधाएँ

| स्क्रीन | विवरण |
|---|---|
| **क्षमता रजिस्टर** | मशीन पर सक्रिय सेवाओं का पता लगाता है और उनके ज्ञात लॉग को एक-एक करके या सभी को इम्पोर्ट करने का प्रस्ताव देता है। अतिरिक्त रूप से किसी फ़ोल्डर का मैनुअल स्कैन। |
| **लाइब्रेरी** | संसाधित किए जाने वाले सभी लॉग का संदर्भ रखने वाला केंद्रीय हब — रजिस्टर, मैनुअल इम्पोर्ट, Omega-Serv के ज्ञात लॉग या SSH से प्राप्त प्रति द्वारा भरा जाता है। |
| **लॉग देखें** | लाइब्रेरी से एक या अधिक लॉग का चयन + व्यूअर का चुनाव (1 लॉग → तीनों व्यूअर; 2+ लॉग → केवल `lnav`)। |
| **पसंदीदा** | किसी नाम से सहेजे गए लॉग + व्यूअर के संयोजन, सीधे खोलने के लिए। |
| **IP देखें और संसाधित करें** | अवधि के अनुसार शीर्ष 10 IP (24 घं/7 दिन/30 दिन/सब), या किसी विशिष्ट IP की खोज (IPv4 या IPv6), और एक या अधिक लॉग से किसी IP को लक्षित रूप से हटाना। |
| **आँकड़े (एक्सेस)** | मात्रा, अद्वितीय IP, त्रुटि दर, शीर्ष IP, प्रति घंटा वितरण — 5 थीम में JSON/HTML एक्सपोर्ट। |
| **Rotate** | किसी लॉग का संपीड़ित बैकअप + अतिरिक्त आर्काइव का स्वचालित रिटेंशन + रिस्टोर (मर्ज या प्रतिस्थापन, सुरक्षा बैकअप के साथ)। **निर्धारित बैकअप**: किसी लॉग का हर दिन, हफ़्ते या महीने बैकअप, जो हर रात systemd टाइमर या आपकी crontab की एक पंक्ति (OpenRC, runit) द्वारा चलाया जाता है, आपके खाते से, कभी root से नहीं। |
| **साफ़ करें** | किसी लॉग की सामग्री खाली करता है (उसी जगह ट्रंकेशन, उस सेवा के लिए सुरक्षित जिसने उसे अभी भी खोल रखा है) या एक या अधिक फ़ाइलों को पूरी तरह हटाता है — हमेशा पुष्टि के साथ। |
| **एक्सपोर्ट** | आर्काइव की सूची (Rotate) को JSON या थीम वाले HTML में एक्सपोर्ट करना। |
| **लॉग स्वास्थ्य** | लाइब्रेरी के लॉग, डिस्क, बैकअप और निर्धारित बैकअप की केवल-पठन जाँच: अनुमतियाँ, मौन या क्षतिग्रस्त लॉग, तिथियाँ, logrotate, डिस्क भरने में बचे दिन, साथ में करने योग्य कदम। बहुत खुली अनुमतियों का सुधार (ज़रूरत हो तो sudo के साथ), JSON/HTML/TXT एक्सपोर्ट। |
| **विकल्प** | थीम, रेंडरिंग प्रोफ़ाइल, इंटरफ़ेस की भाषा और एक्सपोर्ट की भाषा (17 भाषाएँ), एप्लिकेशन फ़ोल्डरों (exports/screenshots) की सफ़ाई। |

### 3 व्यूअर

1. **सरल** — सामान्य पार्सिंग (टाइमस्टैम्प, IP, स्तर, सेवा) और आँकड़ों की छोटी तालिका के साथ लाइव फ़ॉलो। पहचाने गए HTTP access log के लिए अतिरिक्त कॉलम HTTP कोड / विलंब, सीमा के अनुसार रंगीन।
2. **क्लासिक** — अंतिम कच्ची पंक्तियों का पठन + «लाइव फ़ॉलो करें» टॉगल, बिना पार्सिंग के: प्रारूप चाहे जो हो, सबसे सरल और सबसे भरोसेमंद।
3. **lnav** — क्रॉस-विश्लेषण के लिए एक समाहित टर्मिनल (pty) में कई फ़ाइलों का विलय। थीम चक्र (`t`), चिह्नित करना + क्लिपबोर्ड में कॉपी (`Ctrl+C`, OSC 52), बाहर निकलना (`Ctrl+Q`) — सभी `lnav` से पहले ही रोक लिए जाते हैं।

## 5. टर्मिनल संगतता

TUI (Textual) टर्मिनल की क्षमताओं (एमुलेटर, आकार) का स्वचालित रूप से पता लगाता है और उसी के अनुसार अपनी संरचनात्मक स्टाइलशीट (`complete`/`standard`/`reduced`/`mono`) ढालता है, बिना किसी मैनुअल फ़्लैग के — पूरे `omega-` सूट द्वारा साझा वही नीति (`omega-lib`, `terminal/policies.py`)। `r` कुंजी से लाइव ताज़ा किया जा सकता है।

### पहचाने गए एमुलेटर के अनुसार प्रोफ़ाइल

| एमुलेटर | प्रारंभिक प्रोफ़ाइल |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, आधुनिक SSH | `reduced` |
| Linux TTY, पुराना SSH | `mono` |
| अपरिचित एमुलेटर | `reduced` (डिफ़ॉल्ट विकल्प) |

### टर्मिनल के आकार के अनुसार प्रोफ़ाइल

| न्यूनतम आकार (कॉलम × पंक्तियाँ) | प्रोफ़ाइल की ऊपरी सीमा |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| इससे कम | `mono` |

अंततः चुनी गई प्रोफ़ाइल **दोनों में से अधिक प्रतिबंधात्मक** होती है (एमुलेटर और आकार)।

## 6. आर्किटेक्चर

Clean Architecture (डोमेन / एप्लिकेशन / इन्फ़्रास्ट्रक्चर / इंटरफ़ेस), बाकी OMEGA सूट जैसी ही परिपाटी:

```text
src/omega_log/
├── core/            क्षमता रजिस्टर (सेवाओं का पता लगाना)
├── domain/          शुद्ध व्यावसायिक तर्क (पार्सिंग, आँकड़े, रोटेशन, सफ़ाई)
├── ports/           अनुबंध (Protocol)
├── application/     उपयोग के मामले
├── infrastructure/  वास्तविक कार्यान्वयन (probes, भंडारण, आर्काइव, एक्सपोर्ट, lnav, समवर्तिता)
├── interfaces/      TUI (Textual) + CLI
└── app/             Composition root
```

थीम (10 TUI थीम + 5 एक्सपोर्ट थीम), टर्मिनल पहचान और सेटिंग्स के भंडारण के लिए [`omega-lib`](../../../../LIB/omega-lib) पर निर्भर — बाकी सूट जैसा ही आधार। भारी गणनाएँ (शीर्ष IP, एक्सेस आँकड़े) एक समर्पित `ProcessPoolExecutor` (`infrastructure/concurrency/`) में चलती हैं, कभी इंटरफ़ेस थ्रेड पर नहीं, ताकि कई लाख पंक्तियों वाली फ़ाइल पर भी इंटरफ़ेस प्रतिक्रियाशील रहे।
