**Omega-log** — инструмент пакета `omega-`, предназначенный для управления, чтения и анализа серверных журналов в TUI: автоматическое обнаружение активных служб и их журналов, центральная библиотека, три режима чтения (простое отслеживание, классическое чтение, объединение нескольких файлов через `lnav`), обработка IP-адресов, статистика, ротация/резервное копирование/восстановление, безопасная очистка и экспорт. Создан путём **переноса и адаптации** уже зрелого кода [omega-fire](https://github.com/kraynux) и [omega-serv](https://github.com/kraynux), а не написан с нуля.

## 1. Видение и границы

Omega-log отвечает на простой вопрос: «что происходит в моих журналах и как мне с ними работать?» — не завися от жёсткого списка известных путей, никогда не работая от root по умолчанию и никогда не теряя и не повреждая молча настоящий файл журнала.

### Что делает Omega-log

- Автоматически обнаруживает активные службы на машине (веб-серверы, базы данных, почта, DNS, безопасность, `omega-serv`...) и предлагает импортировать их известные журналы по одному или все сразу — в дополнение к ручному сканированию любого каталога.
- Собирает журналы для обработки в единой Библиотеке — точке входа во все остальные экраны.
- Читает журнал в одном из трёх режимов в зависимости от задачи: простое отслеживание с разбором и статистикой, классическое чтение «как есть» с отслеживанием в реальном времени или объединение нескольких файлов во встроенном `lnav`.
- Запоминает сочетания журналы + просмотрщик в Избранном для прямого запуска.
- Вычисляет топ-10 IP-адресов за период или ищет конкретный IP-адрес и позволяет точечно удалить его из одного или нескольких файлов.
- Вычисляет статистику доступа (объём, уникальные IP, доля ошибок, распределение по часам) с экспортом в JSON или HTML с темой.
- Создаёт резервные копии (сжатие + автоматическое хранение) вручную или каждую ночь через запланированные резервные копии, восстанавливает (слияние или перезапись, со страховочной копией) и очищает (усечение на месте или удаление) файлы журналов — всегда с явным подтверждением.
- Проверяет состояние журналов (права, «молчащие» или повреждённые журналы, место на диске, резервные копии) и для каждого замечания говорит, что делать.
- Автоматически подстраивается под возможности терминала (цвета, размер) через `omega-lib`, как и весь пакет.

### Чего Omega-log не делает

| Функция | Ответственный инструмент |
|---|---|
| Межсетевой экран, сетевые правила, обнаружение вторжений | OMEGA-FIRE |
| Веб-сервер, reverse proxy, WAF, Active Defense | OMEGA-SERV |
| Сканирование портов, определение сетевых служб | OMEGA-CHECK |
| Наблюдение за сетью, цифровая идентичность цели | OMEGA-TRACK |

(Пока) нет CLI с полным паритетом с TUI (текущий режим командной строки охватывает только сканирование служб, см. §3.2), нет централизованного сбора с нескольких машин, нет оповещений в реальном времени по порогу — Omega-log остаётся инструментом локального осмотра и обслуживания, а не SIEM.

### Предупреждение об использовании

Действия обслуживания (**Очистить**, **Rotate → Восстановить в режиме Перезапись**) безвозвратно изменяют или стирают реальное содержимое ваших файлов журналов — им всегда предшествует явное подтверждение с перечнем затронутых файлов, и они никогда не запускаются автоматически. Если сомневаетесь, сначала сделайте копию (**Rotate → Создать копию сейчас**).

## 2. Установка

### Требования

- Python 3.10+
- Linux (проверено на Arch/Manjaro, Debian/Ubuntu, RHEL/Fedora)
- `lnav`, установленный в системе, — только для просмотрщика с объединением нескольких файлов (два других просмотрщика нормально работают без него):

```bash
# Arch / Manjaro
sudo pacman -S lnav

# Debian / Ubuntu
sudo apt install lnav
```

### Установка

```bash
[ -d omega-log ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-log-1.6.0.tar.gz
cd omega-log/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv`, если оно ещё не существует.
2. Устанавливает зависимости (сначала встроенную `omega-lib`, если она есть, затем `pip install -e .` — `pyproject.toml` остаётся единственным источником истины).
3. Делает `omega-log.sh` и `install.sh` исполняемыми.
4. Проверяет наличие `lnav` (информационное предупреждение при отсутствии, никогда не блокирующее).
5. Добавляет псевдоним `log` в `~/.bashrc` и `~/.zshrc` (без дублирования, если он уже есть).

### Зависимости

Объявлены в `pyproject.toml` (без отдельного `requirements.txt`):
- `omega-lib`: общая библиотека пакета (темы TUI + экспорта, определение терминала, хранение настроек)
- `textual`: интерфейс TUI
- `jinja2`: экспорт HTML с темой (статистика, архивы)
- `pyte`: эмуляция терминала для просмотрщика `lnav` (отрисовка во встроенном pty)
- Зависимости для разработки (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `ruff`, `mypy`

## 3. Использование

### 3.1. Интерактивный режим (TUI)

Рекомендуется для повседневной работы — запускается без аргументов:

```bash
./omega-log.sh
```
если вы создали псевдоним, просто введите `log` в новом терминале:
```bash
log
```

Общий порядок работы: заставка → главное меню (две колонки — Реестр возможностей/Библиотека/Просмотр журналов/Избранное/IP-адреса: просмотр и обработка/Статистика (доступ) с одной стороны, Rotate/Очистить/Экспорт/Состояние журналов/Параметры/Справка с другой) → экран выбранной функции → возврат в меню (`Esc`). Полная справка (`a`) подробно описывает каждый экран, каждый просмотрщик и общие понятия (разовое повышение прав через sudo, состояния журналов, выбор по номерам) — главное см. в §4.

#### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Перемещение между элементами экрана |
| `Tab` / `Shift+Tab` | Перемещение между полями формы |
| `Esc` | Возврат к предыдущему экрану (на главном экране — подтверждение выхода) |
| `t` | Следующая тема (применяется сразу, без подтверждения) |
| `r` | Обновить определение терминала |
| `a` | Показать справку (исчерпывающую, по главе на экран) |
| `q` | Выход (с подтверждением) |

### 3.2. Режим командной строки (CLI)                                                              

Пока без полного паритета с TUI (избранное, очистка... появятся на своих этапах, см. `plan_omega_log.md` §12):

```bash
# Обнаруживает активные службы и их известные журналы
python -m omega_log scan

# + ручное сканирование дополнительного каталога
python -m omega_log scan --path /var/log

# Установленная версия и сравнение с последней опубликованной версией
python -m omega_log version --check

# Запланированные резервные копии, срок которых наступил (запускается каждую ночь таймером systemd или crontab)
python -m omega_log rotate run-automations
```

### 3.3. Переменные окружения

| Переменная | Действие |
|---|---|
| `OMEGA_LOG_VAR_DIR` | Меняет расположение каталога состояния приложения (по умолчанию `./var`, относительно каталога запуска) |
| `OMEGA_LOG_LANG` | Принудительно задаёт язык интерфейса на время сеанса (напр. `en`, `de`, `ja`), не меняя сохранённую настройку |

## 4. Возможности

| Экран | Описание |
|---|---|
| **Реестр возможностей** | Обнаруживает активные службы на машине и предлагает импортировать их известные журналы по одному или все сразу. Дополнительно — ручное сканирование каталога. |
| **Библиотека** | Центральный узел со ссылками на все журналы для обработки — пополняется из Реестра, ручным импортом, известными журналами Omega-Serv или копией, полученной по SSH. |
| **Просмотр журналов** | Выбор одного или нескольких журналов из Библиотеки + выбор просмотрщика (1 журнал → 3 просмотрщика; 2+ журнала → только `lnav`). |
| **Избранное** | Сочетания журналы + просмотрщик, сохранённые под именем, для прямого запуска. |
| **IP-адреса: просмотр и обработка** | Топ-10 IP-адресов за период (24ч/7д/30д/всё) или поиск конкретного IP-адреса (IPv4 или IPv6) и точечное удаление IP из одного или нескольких журналов. |
| **Статистика (доступ)** | Объём, уникальные IP, доля ошибок, топ IP, распределение по часам — экспорт JSON/HTML с 5 темами. |
| **Rotate** | Сжатая резервная копия журнала + автоматическое хранение с удалением лишних архивов + восстановление (слияние или перезапись, со страховочной копией). **Запланированные резервные копии**: журнал копируется ежедневно, еженедельно или ежемесячно, запуск каждую ночь таймером systemd или строкой в вашем crontab (OpenRC, runit), от вашей учётной записи, никогда от root. |
| **Очистить** | Опустошает содержимое журнала (усечение на месте, безопасное для службы, которая ещё держит его открытым) или полностью удаляет один или несколько файлов — всегда с подтверждением. |
| **Экспорт** | Экспорт списка архивов (Rotate) в JSON или HTML с темой. |
| **Состояние журналов** | Проверка только для чтения журналов Библиотеки, диска, резервных копий и запланированных резервных копий: права, «молчащие» или повреждённые журналы, даты, logrotate, дни до заполнения диска — с указанием, что делать. Исправление слишком широких прав (при необходимости через sudo), экспорт JSON/HTML/TXT. |
| **Параметры** | Тема, режим отображения, язык интерфейса и язык экспорта (17 языков), очистка каталогов приложения (exports/screenshots). |

### 3 просмотрщика

1. **Простой** — отслеживание в реальном времени с универсальным разбором (метка времени, IP, уровень, служба) и мини-таблицей статистики. Для распознанного журнала доступа HTTP — дополнительные столбцы код HTTP / задержка с цветом по порогам.
2. **Классический** — чтение последних строк «как есть» + переключатель «Отслеживать», без разбора: самый простой и самый надёжный при любом формате.
3. **lnav** — объединение нескольких файлов во встроенном терминале (pty) для перекрёстного анализа. Смена темы (`t`), выделение + копирование в буфер обмена (`Ctrl+C`, OSC 52), выход (`Ctrl+Q`) — всё перехватывается до самого `lnav`.

## 5. Совместимость с терминалами

TUI (Textual) автоматически определяет возможности терминала (эмулятор, размер) и соответственно адаптирует свою структурную таблицу стилей (`complete`/`standard`/`reduced`/`mono`) без ручного флага — та же политика действует во всём пакете `omega-` (`omega-lib`, `terminal/policies.py`). Обновляется на лету клавишей `r`.

### Профиль по обнаруженному эмулятору

| Эмулятор | Начальный профиль |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, современный SSH | `reduced` |
| TTY Linux, устаревший SSH | `mono` |
| Нераспознанный эмулятор | `reduced` (запасной вариант по умолчанию) |

### Профиль по размеру терминала

| Минимальный размер (столбцы × строки) | Предельный профиль |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| меньше | `mono` |

Итоговым выбирается **более строгий из двух** профилей (эмулятор и размер).

## 6. Архитектура

Clean Architecture (домен / приложение / инфраструктура / интерфейсы), то же соглашение, что и во всём пакете OMEGA:

```text
src/omega_log/
├── core/            Реестр возможностей (обнаружение служб)
├── domain/          Чистая бизнес-логика (разбор, статистика, ротация, очистка)
├── ports/           Контракты (Protocol)
├── application/     Сценарии использования
├── infrastructure/  Реальные реализации (зонды, хранение, архивы, экспорт, lnav, параллелизм)
├── interfaces/      TUI (Textual) + CLI
└── app/             Composition root
```

Зависит от [`omega-lib`](../../../../LIB/omega-lib) в части тем (10 тем TUI + 5 тем экспорта), определения терминала и хранения настроек — та же основа, что и у всего пакета. Тяжёлые вычисления (топ IP, статистика доступа) выполняются в отдельном `ProcessPoolExecutor` (`infrastructure/concurrency/`), никогда в потоке интерфейса, чтобы оставаться отзывчивым даже на файле в несколько сотен тысяч строк.

Структура: `tests/unit/` (домен и приложение, без реального ввода-вывода), `tests/integration/` (реальные файлы, TUI без экрана через API `Pilot` в Textual).

## 8. Состояние разработки

Все 10 этапов плана разработки завершены: основа, домен, базовый TUI, просмотрщики, избранное/библиотека/IP, обслуживание, статистика/экспорт, финализация, разовое повышение прав через sudo, вынос ресурсоёмких для CPU вычислений в отдельный процесс — подробности каждого решения о переносе см. в `plan_omega_log.md`. Начиная с 1.6.0 перенесены новые возможности менеджера журналов omega-serv 2.6.0: Состояние журналов, запланированные резервные копии, поиск конкретного IP-адреса, отображение версии и проверка обновлений.
