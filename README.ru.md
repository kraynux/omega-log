**Omega-log** — инструмент набора `omega-`, предназначенный для управления, чтения и анализа файлов серверных логов в TUI-интерфейсе — автоматическое обнаружение активных служб и их логов, центральная библиотека, три режима чтения (простой просмотр, классическое чтение, слияние нескольких файлов через `lnav`), обработка IP-адресов, статистика, ротация/резервное копирование/восстановление, безопасная очистка и экспорт. Создан путём **переноса и адаптации** уже зрелого кода из [omega-fire](https://github.com/kraynux) и [omega-serv](https://github.com/kraynux), а не написан с нуля.

## 1. Назначение и границы

Omega-log отвечает на простой вопрос: «что происходит в моих логах, и как с этим разобраться?» — без привязки к фиксированному списку известных путей, никогда не запускаясь от root по умолчанию и никогда не теряя и не повреждая молча реальный файл лога.

### Что умеет Omega-log

- Автоматически обнаруживает активные службы на машине (веб-серверы, базы данных, почта, DNS, безопасность, `omega-serv`...) и предлагает импорт их известных логов — детально или целиком, в дополнение к ручному сканированию любой папки.
- Централизует логи для обработки в единой Библиотеке — точке входа для всех остальных экранов.
- Читает лог в одном из трёх режимов по потребности: простой просмотр с разбором и статистикой, классическое чтение в исходном виде с live-слежением, либо слияние нескольких файлов с обёрткой `lnav`.
- Запоминает комбинации лог(и) + просмотрщик как Избранное, для прямого запуска.
- Вычисляет топ-10 IP-адресов за период и позволяет точечно удалить их из одного или нескольких файлов.
- Вычисляет статистику доступа (объём, уникальные IP, доля ошибок, распределение по часам) с экспортом в JSON или тематизированный HTML.
- Резервирует (сжатие + автоматическое хранение), восстанавливает (слияние или перезапись, с предварительной резервной копией) и очищает (обрезка на месте или удаление) файлы логов — всегда с явным подтверждением.
- Автоматически подстраивается под возможности терминала (цвета, размер) через `omega-lib`, как и весь остальной набор.

### Чего Omega-log не делает

| Функция | Отвечающий инструмент |
|---|---|
| Межсетевой экран, сетевые правила, обнаружение вторжений | OMEGA-FIRE |
| Веб-сервер, обратный проксиc, WAF, Active Defense | OMEGA-SERV |
| Сканирование портов, определение сетевых служб | OMEGA-CHECK |
| Сетевое наблюдение, цифровая идентичность цели | OMEGA-TRACK |

Пока нет CLI с полным паритетом с TUI (текущий режим командной строки покрывает только сканирование служб, см. §3.2), нет централизованной агрегации по нескольким машинам, нет оповещений в реальном времени по порогу — Omega-log остаётся инструментом локального осмотра и обслуживания, а не SIEM.

### Предупреждение об использовании

Действия обслуживания (**Очистка**, **Rotate → Восстановление в режиме перезаписи**) окончательно изменяют или удаляют реальное содержимое ваших файлов логов — всегда предваряются явным подтверждением с перечнем затронутых файлов, никогда не запускаются автоматически. В случае сомнений сделайте резервную копию (**Rotate → Сделать резервную копию сейчас**) перед действием.

## 2. Установка

### Требования

- Python 3.10+
- Linux (проверено на Arch/Manjaro, Debian/Ubuntu, RHEL/Fedora)
- `lnav`, установленный в системе — только для просмотрщика слияния нескольких файлов (два других просмотрщика нормально работают без него):

```bash
# Arch / Manjaro
sudo pacman -S lnav

# Debian / Ubuntu
sudo apt install lnav
```

### Установка

```bash
[ -d omega-log ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-log.tar.gz
cd omega-log/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv`, если оно ещё не существует.
2. Устанавливает зависимости (сначала вендорную `omega-lib`, если присутствует, затем `pip install -e .` — `pyproject.toml` остаётся единственным источником истины).
3. Делает `omega-log.sh` и `install.sh` исполняемыми.
4. Проверяет наличие `lnav` (информационное предупреждение при отсутствии, никогда не блокирующее).
5. Добавляет алиас `log` в `~/.bashrc` и `~/.zshrc` (без дублирования, если уже присутствует).

### Зависимости

Объявлены в `pyproject.toml` (без отдельного `requirements.txt`):
- `omega-lib`: общая библиотека набора (темы TUI + экспорт, определение терминала, хранение настроек)
- `textual`: фреймворк TUI
- `jinja2`: тематизированный HTML-экспорт (статистика, архивы)
- `pyte`: эмуляция терминала для просмотрщика `lnav` (рендеринг внутри обёрнутого pty)
- Зависимости для разработки (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `ruff`, `mypy`

## 3. Использование

### 3.1. Интерактивный режим (TUI)

Рекомендуется для повседневного использования — запускается без аргументов:

```bash
./omega-log.sh
```
если вы создали алиас, просто введите `log` в новом терминале:
```bash
log
```

Общий сценарий: экран приветствия → главное меню (два столбца — Реестр/Библиотека/Просмотр логов/Избранное/Просмотр и обработка IP/Статистика с одной стороны, Rotate/Очистка/Экспорт/Настройки/Справка/Выход с другой) → выбранный экран → возврат в меню (`Escape`). Полная встроенная справка (`a`) подробно описывает каждый экран, каждый просмотрщик и сквозные концепции (разовое повышение прав sudo, состояния логов, выбор по номерам) — суть изложена в §4.

#### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Навигация между элементами экрана |
| `Tab` / `Shift+Tab` | Навигация между полями формы |
| `Escape` | Назад к предыдущему экрану (подтверждение выхода на главном экране) |
| `t` | Следующая тема (применяется немедленно, без подтверждения) |
| `r` | Обновить определение терминала |
| `a` | Показать справку (исчерпывающую, по одной главе на экран) |
| `q` | Выход (с подтверждением) |

### 3.2. Режим командной строки (CLI)

На данный момент ограничен сканированием служб (пока без полного паритета с TUI — избранное, rotate, очистка появятся со своими фазами, см. `plan_omega_log.md` §12):

```bash
# Обнаружить активные службы и их известные логи
python -m omega_log scan

# + ручное сканирование дополнительной папки
python -m omega_log scan --path /var/log
```

### 3.3. Переменные окружения

| Переменная | Эффект |
|---|---|
| `OMEGA_LOG_VAR_DIR` | Меняет расположение папки состояния приложения (по умолчанию `./var`, относительно папки запуска) |

## 4. Возможности

| Экран | Описание |
|---|---|
| **Реестр возможностей** | Обнаруживает активные службы на машине и предлагает импорт их известных логов — детально или целиком. Дополнительно доступно ручное сканирование папки. |
| **Библиотека** | Центральный узел, ссылающийся на все логи для обработки — пополняется из Реестра или ручным импортом. |
| **Просмотр логов** | Выбор одного или нескольких логов из Библиотеки + выбор просмотрщика (1 лог → все 3 просмотрщика; 2+ логов → только `lnav`). |
| **Избранное** | Сохранённые под именем комбинации лог(и) + просмотрщик, для прямого запуска. |
| **Просмотр и обработка IP** | Топ-10 IP за период (24ч/7д/30д/всё) и точечное удаление IP из одного или нескольких логов. |
| **Статистика (доступ)** | Объём, уникальные IP, доля ошибок, топ IP, распределение по часам — экспорт в JSON/HTML с 5 темами. |
| **Rotate** | Сжатая резервная копия лога + автоматическое хранение избыточных архивов + восстановление (слияние или перезапись, с предварительной резервной копией). |
| **Очистка** | Очищает содержимое лога (обрезка на месте, безопасно для службы, которая его ещё держит открытым) или полностью удаляет один или несколько файлов — всегда с подтверждением. |
| **Экспорт** | Экспорт списка архивов (Rotate) в JSON или тематизированный HTML. |
| **Настройки** | Тема, профиль рендеринга, очистка папок приложения (exports/screenshots). |

### 3 просмотрщика

1. **Простой** — live-просмотр с общим разбором (метка времени, IP, уровень, служба) и небольшой панелью статистики. Для распознанного HTTP access-лога появляются дополнительные столбцы с HTTP-кодом и задержкой, окрашенные по порогу.
2. **Классический** — читает последние строки в исходном виде + переключатель «Следить в реальном времени», без разбора: самый простой и надёжный вариант независимо от формата.
3. **lnav** — объединяет несколько файлов внутри обёрнутого терминала (pty), для перекрёстного анализа. Переключение темы (`t`), пометка + копирование в буфер (`Ctrl+C`, OSC 52), выход (`Ctrl+Q`) — все перехватываются до того, как достигают самого `lnav`.

## 5. Совместимость с терминалами

TUI (Textual) автоматически определяет возможности терминала (эмулятор, размер) и соответствующим образом адаптирует свою структурную таблицу стилей (`complete`/`standard`/`reduced`/`mono`), без ручных флагов — та же политика, общая для всего набора `omega-` (`omega-lib`, `terminal/policies.py`). Обновляется вживую по клавише `r`.

### Профиль по определённому эмулятору

| Эмулятор | Начальный профиль |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, современный SSH | `reduced` |
| Linux TTY, устаревший SSH | `mono` |
| Нераспознанный эмулятор | `reduced` (резервный вариант по умолчанию) |

### Профиль по размеру терминала

| Минимальный размер (столбцы × строки) | Потолок профиля |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| ниже | `mono` |

Итоговый используемый профиль — **более строгий из двух** (эмулятор и размер).

## 6. Архитектура

Чистая архитектура (domain / application / infrastructure / interfaces) — та же конвенция, что и во всём наборе OMEGA:

```text
src/omega_log/
├── core/            Реестр возможностей (обнаружение служб)
├── domain/          Чистая бизнес-логика (парсинг, статистика, ротация, очистка)
├── ports/           Контракты (Protocol)
├── application/     Сценарии использования
├── infrastructure/  Реальные реализации (зонды, хранилище, архивы, экспорт, lnav, параллелизм)
├── interfaces/      TUI (Textual) + CLI
└── app/             Корень композиции
```

Зависит от [`omega-lib`](../LIB/omega-lib) для тем (10 тем TUI + 5 тем экспорта), определения терминала и хранения настроек — та же основа, что и у остального набора. Тяжёлые вычисления (топ IP, статистика доступа) выполняются в выделенном `ProcessPoolExecutor` (`infrastructure/concurrency/`), никогда в потоке интерфейса, чтобы оставаться отзывчивым даже на файле из сотен тысяч строк.
